# Развёртывание, данные и то, что нужно согласовать до внедрения

## Где что лежит

| Что | Где | Комментарий |
|---|---|---|
| Исходники | папка проекта | `backend/` — сервер, `frontend/` — клиент, `e2e/` — сквозные тесты |
| База данных | `%LOCALAPPDATA%\DolcePharmLMS\pgdata` | PostgreSQL 16, слушает только `127.0.0.1:54329` |
| Загруженные материалы, PDF-копии, сертификаты | `%LOCALAPPDATA%\DolcePharmLMS\demo\files` | имя файла — его SHA-256 |
| Журналы сервера | `%LOCALAPPDATA%\DolcePharmLMS\demo\logs\lms.log` | до 5 файлов по 5 МБ |
| Резервные копии | `%LOCALAPPDATA%\DolcePharmLMS\demo\backups` | команда `start.bat backup` |
| Сертификаты HTTPS | `%LOCALAPPDATA%\DolcePharmLMS\certs` | корневой — на 10 лет, серверный перевыпускается при каждом запуске |

Данные лежат вне папки проекта по двум причинам: PostgreSQL на Windows не запускается из пути с кириллицей, а OneDrive не должен синхронизировать файлы работающей базы.

Контур `test` (автотесты) хранит свою базу `lms_test` и свои файлы в `%LOCALAPPDATA%\DolcePharmLMS\test` и работает на портах 8100/8543. `start.bat` и `reset-demo.bat` всегда работают с демонстрационным контуром; тестовый сервер поднимает сам `run-tests.bat`.

## Команды

Все команды выполняются из папки проекта.

| Команда | Что делает |
|---|---|
| `start.bat` | запускает сервер: база, миграции, сертификат, порты 8000 (HTTP) и 8443 (HTTPS) |
| `start.bat backup` | копия базы (`pg_dump`) и архив файлов |
| `start.bat migrate` | применяет миграции Alembic |
| `start.bat make-migration "описание"` | создаёт миграцию по изменениям моделей |
| `start.bat openapi` | сохраняет описание API в `docs/openapi.json` |
| `start.bat stop-db` | останавливает встроенный PostgreSQL |
| `reset-demo.bat` | стирает контур и загружает демоданные заново |
| `run-tests.bat` | pytest и Playwright в контуре `test` |

## Перенос на сервер предприятия

Прототип рассчитан на один ноутбук. Для промышленной установки на оборудовании в Казахстане меняются только настройки окружения, код остаётся тем же.

| Переменная | Значение по умолчанию | Для сервера |
|---|---|---|
| `LMS_DATABASE_URL` | встроенный PostgreSQL | `postgresql+psycopg://lms:пароль@db-host:5432/lms` — отдельный сервер БД с резервированием |
| `LMS_DATA_DIR` | `%LOCALAPPDATA%\DolcePharmLMS` | постоянный том для файлов, журналов и копий |
| `LMS_HTTPS_PORT`, `LMS_HTTP_PORT` | 8443, 8000 | за обратным прокси (nginx, Caddy) с сертификатом внутреннего удостоверяющего центра предприятия |
| `LMS_UTC_OFFSET_HOURS` | 5 | часовой пояс дат в документах |
| `LMS_TOKEN_TTL_DAYS` | 30 | срок действия входа на устройстве |
| `LMS_MAX_UPLOAD_MB` | 300 | предел размера одного материала |
| `LMS_SOFFICE` | автопоиск | путь к `soffice`, если LibreOffice установлен в нестандартное место |

Что сделать при переносе:

1. Установить LibreOffice на сервер. Он подхватится автоматически и даст более точные PDF-копии сложных документов Office (диаграммы, SmartArt). Сейчас работает встроенный конвертер.
2. Выдать серверу сертификат от удостоверяющего центра предприятия — тогда на телефоны не нужно ставить корневой сертификат вручную.
3. Настроить ежедневный `pg_dump` и копирование папки файлов на отдельный носитель; проверить восстановление.
4. Сменить демонстрационные пароли, отключить демонстрационные учётные записи.
5. Ограничить доступ к порту сервера сетью предприятия.

Внешняя телеметрия отсутствует: клиент обращается только к своему серверу (это закреплено заголовком Content-Security-Policy `connect-src 'self'`), шрифты, иконки, просмотрщик PDF и документация API отдаются с того же сервера.

## Что защищено в прототипе

- Пароли хранятся в виде PBKDF2-SHA256 с солью. После 8 неудачных попыток вход блокируется на 5 минут.
- Токен сессии — случайная строка; в базе хранится только её хэш. Выход отзывает токен.
- По сети без шифрования доступна только страница подключения телефона. Всё остальное перенаправляется на HTTPS.
- Роли проверяет сервер на каждом запросе: сотрудник видит свои записи и файлы своих назначений, руководитель — своё подразделение, методист — всё.
- Правильные ответы тестов на устройство не передаются, проверку выполняет сервер.
- Действия методиста (публикация, назначение, проверка, импорт, выгрузка протокола) пишутся в журнал аудита (таблица `audit_log`).
- На телефоне у каждого сотрудника отдельная локальная база. «Профиль → Очистить данные на этом устройстве» удаляет курсы, справочники и историю; неотправленные ответы сохраняются до отправки.

## Что нужно согласовать до внедрения

Прототип работает только с вымышленными данными. Перед загрузкой сведений о реальных сотрудниках предприятию нужно принять решения, которые выходят за рамки разработки. Юридическое заключение в результат прототипа не входит; ориентир — Закон РК «О персональных данных и их защите», в частности статья 12 о хранении.

| Вопрос | Что решить | Кто решает |
|---|---|---|
| Основание обработки | На каком основании обрабатываются ФИО, табельный номер, результаты аттестации и время обучения: трудовой договор, локальный акт, согласие. Нужно ли отдельное согласие на учёт времени активности | юрист, отдел кадров |
| Состав данных | Достаточно ли табельного номера и ФИО. Нужны ли должность и подразделение в сертификате и протоколе | отдел обучения, отдел кадров |
| Сроки хранения | Сколько хранить попытки, ответы на открытые вопросы, интервалы времени, журналы входов, сертификаты и протоколы. Что делать с данными уволенных | юрист, отдел обеспечения качества (требования GMP к записям об обучении) |
| Место хранения | Сервер и резервные копии на территории Казахстана; кто администрирует; кто имеет доступ к копиям | ИТ-служба, служба безопасности |
| Доступ к отчётам | Кто видит персональные результаты: методист, руководитель подразделения, отдел качества. Нужен ли обезличенный режим для оценки 360 | отдел обучения, руководство |
| Личные смартфоны | Разрешено ли использовать личные устройства. Правило очистки: сейчас приложение рекомендует очистку через 14 дней после сдачи (настраивается). Что делать при утере телефона — отзыв входа уже есть, на устройстве остаются только учебные материалы и собственные ответы сотрудника | служба безопасности, отдел кадров |
| Корневой сертификат на личном телефоне | Допустима ли установка сертификата предприятия на личное устройство или нужен сертификат публичного удостоверяющего центра на внутреннем имени | ИТ-служба |
| Оценка 180/360 | Кто видит индивидуальные оценки коллег. В прототипе их видит только методист в виде сводки; участники видят только свои ответы | отдел кадров, руководство |
| Уведомление уполномоченного органа и локальные акты | Требуются ли регистрация базы, назначение ответственного за обработку, перечень лиц с доступом | юрист |
