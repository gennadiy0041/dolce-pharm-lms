# Подключение телефона

Телефон открывает платформу по локальной сети с ноутбука. Интернет не нужен. Настройка делается один раз и занимает около трёх минут.

## 1. Сеть

Телефон и ноутбук должны быть в одной сети Wi-Fi. Есть два рабочих варианта.

| Вариант | Адрес ноутбука | Когда выбирать |
|---|---|---|
| Общий Wi-Fi (роутер в аудитории) | меняется от сети к сети, виден в окне сервера | если сеть известна заранее и не изолирует устройства друг от друга |
| «Мобильный хот-спот» Windows на ноутбуке | всегда `192.168.137.1` | надёжнее для защиты: адрес постоянный, от чужой сети не зависим |

Хот-спот включается так: **Параметры → Сеть и Интернет → Мобильный хот-спот → Вкл.** Телефон подключается к сети ноутбука как к обычному Wi-Fi.

Три вещи, о которых нужно помнить при работе через хот-спот:

- **Выключите «Энергосбережение»** в том же окне («Отключать мобильный хот-спот, когда устройства не подключены»). Иначе, пока телефон в авиарежиме, Windows сам выключит хот-спот — и после возврата связи телефону будет некуда подключаться.
- **После перезагрузки ноутбука хот-спот нужно включить заново** — Windows не включает его сам. Порядок: включить хот-спот → запустить `start.bat`. Адрес при этом тот же, `https://192.168.137.1:8443`, поэтому ярлык на телефоне продолжает работать, а скачанные курсы остаются на месте.
- Windows включает хот-спот, только когда сам ноутбук подключён к какой-нибудь сети (Wi-Fi или кабель). Интернет в этой сети платформе не нужен: все файлы приложения лежат на ноутбуке.

Адрес, выданный обычной сетью Wi-Fi (например, `172.16.3.110`), постоянным считать нельзя: его назначает роутер, и после перезагрузки или в другом помещении он может стать другим. Приложение на телефоне привязано к адресу, с которого его установили: при новом адресе ярлык не откроется, а курсы придётся скачивать заново. Имя ноутбука вида `имя.local` на телефоне Android в проверенной сети не определялось, поэтому на него рассчитывать не стоит.

Раздавать сеть **с телефона** для показа не подходит: в авиарежиме телефон выключит точку доступа, ноутбук потеряет сеть и сам к ней не вернётся.

Адрес платформы привязан к IP ноутбука. Если после настройки сменить сеть, адрес изменится и скачанные курсы придётся скачать заново. Поэтому настраивайте телефон в той же сети, в которой будет защита.

## 2. Брандмауэр Windows

При первом запуске `start.bat` Windows спросит, разрешить ли Python доступ к сети. Отметьте **и частные, и общедоступные сети** и нажмите «Разрешить доступ».

Если окно закрыли или нажали «Отмена», Windows запомнила для Python запрет, и одного разрешающего правила мало — запрет сильнее. Исправить можно двумя способами.

Через настройки: **Безопасность Windows → Брандмауэр и защита сети → Разрешить работу с приложением через брандмауэр → Изменить параметры** → найдите в списке Python и отметьте оба столбца, «Частная» и «Публичная».

Или в PowerShell от имени администратора — сначала убрать запрет, затем разрешить порты платформы:

```powershell
Get-NetFirewallRule -DisplayName "python*" | Where-Object Action -eq Block | Remove-NetFirewallRule
```

```powershell
netsh advfirewall firewall add rule name="Dolce Pharm LMS" dir=in action=allow protocol=TCP localport=8000,8443
```

## 3. Сертификат (один раз)

Работа без сети возможна только по защищённому адресу `https://`. Сервер сам создаёт сертификат на ноутбуке; телефону нужно один раз сказать, что этому сертификату можно доверять.

1. На ноутбуке войдите как методист и откройте **Настройки и телефон**. Там два QR-кода.
2. Наведите камеру телефона на первый QR-код («Первый раз»). Откроется страница `http://<адрес ноутбука>:8000/phone`.
3. Нажмите **«Скачать сертификат»**.

**Android (Chrome):**

1. Настройки → в поиске наберите «сертификат» → **Установить сертификат** → **Сертификат ЦС** (на некоторых телефонах: Безопасность → Дополнительные настройки → Шифрование и учётные данные).
2. Нажмите «Всё равно установить», выберите скачанный файл `dolce-lms-root-ca.crt`.

**iPhone (Safari):**

1. Разрешите загрузку профиля. Настройки → «Профиль загружен» → Установить.
2. Настройки → Основные → Об этом устройстве → **Доверие сертификатам** → включите «Dolce Pharm LMS Root CA».

После защиты сертификат можно удалить там же, где он устанавливался.

## 4. Платформа и ярлык

1. Наведите камеру на второй QR-код («Платформа») или откройте `https://<адрес ноутбука>:8443`. Предупреждений о безопасности быть не должно. Если браузер пишет «Подключение не защищено», сертификат из шага 3 не установлен.
2. Войдите под учётной записью сотрудника — логины и пароли в `README.md`, раздел «Демодоступы».
3. Поставьте ярлык: в Chrome — меню ⋮ → **«Добавить на главный экран» → «Установить»**; в Safari — «Поделиться» → **«На экран “Домой”»**.
4. **Закройте в Chrome вкладку с платформой** (кнопка с числом вкладок → крестик на вкладке) и откройте платформу **с ярлыка**.

Закрыть вкладку обязательно. Установленное приложение и вкладка Chrome пользуются одним хранилищем на телефоне. Вкладка, оставшаяся в фоне, через несколько минут замораживается Android и может удерживать это хранилище: тогда приложение зависает на «Загружаем…», а скачивание курса обрывается. Так случилось 21.11.2026 на POCO X7 Pro; после закрытия вкладки приложение сразу заработало, данные не пострадали.

## 5. Проверка, что Service Worker зарегистрирован

В приложении: **Профиль → Проверка автономной работы**. Должно быть «Да» в строках:

- защищённый адрес (HTTPS);
- Service Worker зарегистрирован;
- оболочка приложения сохранена на устройстве;
- запущено с домашнего экрана.

Строка «фоновая отправка (Background Sync)» показывает «Да» в Chrome на Android и «Нет» в Safari на iPhone — это ограничение iOS, см. раздел 7.

Дополнительно в Chrome на Android можно открыть `chrome://serviceworker-internals` и найти в списке адрес платформы со статусом ACTIVATED.

### Как телефон получает другую сборку

Сервер отдаёт одну из двух сборок интерфейса (`switch-build.bat 1` или `2`, см. `README.md`). Установленное приложение обновляется само: при включённой сети открыть его с иконки, смахнуть и открыть ещё раз — первый запуск скачивает новую сборку, второй уже показывает её. Скачанные курсы и несданные ответы при этом остаются на месте.

Признак сборки 2 — логотип Dolce-Pharm в белой шапке; у сборки 1 шапка зелёная. Иконка на главном экране меняется позже: Chrome обновляет её сам, обычно в течение суток. Чтобы новая иконка появилась сразу, приложение удаляют с главного экрана и устанавливают заново (раздел 4); курсы после этого скачиваются заново.

## 6. Репетиция сценария без сети

1. С сетью: на главном экране нажмите **«Скачать для работы без сети»**, дождитесь отметки **«Готово без сети»**.
2. Включите авиарежим. Убедитесь, что Wi-Fi выключен (при авиарежиме его иногда можно включить отдельно — он должен быть выключен).
3. Смахните приложение из списка запущенных и откройте его **с ярлыка**.
4. Откройте материалы: PDF, видео (перемотайте), Word, Excel, PowerPoint. Пройдите тест. Должно появиться **«Ответы сохранены на телефоне»**.
5. Верните связь: выключите авиарежим или, не выключая его, включите только Wi-Fi. Телефон сам подключится к сети, приложение само отправит ответы. На ноутбуке в «Отчёте по обучению» появится строка.

## 7. Проверка на физическом телефоне

Автотесты проходят эти шаги в Chromium на ноутбуке. На настоящем телефоне их проходят руками. Первый такой прогон сделан 20.11.2026 на POCO X7 Pro (Android 15, Chrome 152); результаты — в `docs/МАТРИЦА.md`, раздел «Физический телефон».

| Что проверить | Как | Состояние |
|---|---|---|
| Установка ярлыка | шаги 3–5 | пройдено: приложение встало как WebAPK |
| Запуск в авиарежиме после полного закрытия | раздел 6, шаги 2–4 | пройдено дважды |
| Автодоставка, приложение открыто | после сдачи вернуть связь, смотреть на ноутбук | пройдено: не больше 2 с |
| Автодоставка, приложение закрыто | сдать тест без сети, смахнуть приложение, вернуть связь, приложение не открывать | пройдено один раз: 1,6 с после двух минут без сети |
| Автодоставка, приложение свёрнуто | сдать тест без сети, свернуть приложение (кнопка «Домой»), вернуть связь, приложение не открывать | **не пройдено** |
| Автодоставка после долгого простоя или при экономии заряда | то же, но телефон лежит без сети час и больше | **не пройдено** |
| Время изучения | 60 секунд читать материал по секундомеру, на 60 секунд свернуть, вернуться, выйти из материала | **не пройдено** |
| Другой телефон, iPhone | весь раздел 6 | **не пройдено** |

Замер делается с ноутбука, а не по секундомеру:

```powershell
.\.venv\Scripts\python.exe tools\phone_watch.py --phone-ip 192.168.137.85 --label run3
```

Скрипт каждые полсекунды проверяет, отвечает ли телефон в сети, и читает из базы момент приёма записей. Задержка — разница между «телефон снова отвечает» и «сервер принял». Адрес телефона виден в его настройках Wi-Fi. Журнал пишется в `e2e\results\phone`. Что методист видит по сотруднику после прогона, одним списком показывает `tools\run_report.py --login operator`.

Чего ждать по фоновой доставке:

- **Chrome на Android** поддерживает Background Sync: при закрытом приложении браузер будит Service Worker после возврата связи. На проверенном телефоне это заняло секунды. Срок зависит от режима энергосбережения, гарантии система не даёт.
- **Safari на iPhone** Background Sync не поддерживает. Ответы сохранятся и уйдут при следующем открытии приложения. Это ограничение платформы, в матрице оно отмечено отдельной строкой.

Если на целевых телефонах закрытое приложение не укладывается в 30 минут, а фоновая доставка обязательна, следующий шаг — Android-клиент с системной фоновой задачей (WorkManager) поверх того же API и того же формата событий. В прототип он не входит.

## Если что-то пошло не так

| Признак | Причина и действие |
|---|---|
| Приложение висит на «Загружаем…» или скачивание курса обрывается | В Chrome осталась вкладка с платформой и держит хранилище. Откройте Chrome → кнопка с числом вкладок → закройте вкладку с адресом платформы. Приложение оживает сразу, данные на месте (раздел 4) |
| Телефон не открывает страницу вообще | Разные сети, или брандмауэр блокирует Python (раздел 2), или роутер изолирует устройства — включите хот-спот ноутбука |
| После авиарежима телефон не находит сеть хот-спота | Windows выключил хот-спот, пока к нему никто не был подключён. Включите его снова и выключите «Энергосбережение» (раздел 1). Сервер перезапускать не нужно |
| «Подключение не защищено» | Сертификат не установлен или установлен как «сертификат пользователя» вместо «сертификата ЦС» |
| В «Проверке автономной работы» Service Worker — «Нет» | Обновите страницу один раз при включённой сети |
| После смены сети приложение не открывается | Адрес ноутбука изменился. Перезапустите `start.bat`, откройте новый адрес, скачайте курс заново |
| Ответы «ждут отправки» при включённой сети | Нажмите на плашку статуса вверху → «Отправить сейчас». Если пишет «Нужен вход» — войдите заново, ответы сохранены |
| После `reset-demo.bat` телефон пишет «Войдите заново» | Так и должно быть: учётные записи пересозданы. Войдите и выполните «Профиль → Очистить данные на этом устройстве» |
| Во второй вкладке того же браузера открылся тот же пользователь | Вкладки одного браузера делят учётную запись. Для второй роли откройте окно инкогнито или другой браузер |
